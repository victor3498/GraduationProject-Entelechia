## 生成文档分享码

用例名称	生成文档分享码
用例ID	UC10
角色	已登录用户（文档所有者）
用例说明	文档所有者为指定文档生成只读或可编辑分享链接，系统返回分享码供其复制分享
前置条件	用户已登录，且进入自己拥有的文档的分享管理对话框
基本事件流	                                               参与者动作：
1.1 点击文档列表中的"分享"按钮或编辑器顶栏"分享"按钮          1.2 系统弹出 ShareDialog，并查询当前文档已生效的分享码列表
2.1 选择权限类型（"只读"或"可编辑"）并点击"生成"按钮            2.2 系统校验该文档当前权限下是否已存在生效记录，若已存在则直接返回现有分享码，否则生成新的随机分享码并入库
3.1 点击"复制链接"按钮                                        3.2 系统将完整分享 URL 写入剪贴板，提示"已复制"


其他事件流	2.2.1 同一权限分享码已存在：系统直接返回已有分享码，不重复创建
异常事件流	2.2.2 分享码生成冲突（随机码重复）：系统自动重试一次生成新随机码，若仍冲突则提示"生成失败，请重试"
后置条件	数据库中存在对应文档、对应权限的一条生效分享记录（is_active=true），用户已获得可分发的分享链接
备注	每文档每种权限最多同时存在一条生效记录，由数据库部分唯一索引（idx_active_share_per_perm）保证

## 通过分享码进入文档

用例名称	通过分享码进入文档
用例ID	UC11
角色	任意用户（含未登录游客）
用例说明	用户输入他人提供的分享码，系统验证后跳转至对应的共享文档页面
前置条件	用户位于分享码输入页（/share 或 /mobile/share），或直接访问分享链接
基本事件流	                                               参与者动作：
1.1 在登录页或主页点击"通过分享码访问"入口                      1.2 系统跳转至分享码输入页（/share），并记录来源页路径
2.1 在输入框填写分享码并点击"提交"                             2.2 系统向后端发送 GET /api/share/:code 请求，校验分享码是否存在且生效
3.1 —                                                       3.3 校验通过，系统跳转至共享文档页面（/share/:code），并携带来源页信息


其他事件流	无
异常事件流	2.2.1 分享码不存在或已被撤销：系统在共享文档页面展示"该分享链接已撤销或不存在"提示，并显示返回按钮
后置条件	用户进入共享文档页面，页面根据分享权限展示只读视图或可编辑视图
备注	分享码路由为公开路由，无需登录；前端 http 拦截器对 /share/* 路径跳过自动重定向，保证游客正常访问

## 查看只读共享文档

用例名称	查看只读共享文档
用例ID	UC12
角色	任意用户（含未登录游客）
用例说明	持有只读分享码的用户访问共享文档，系统展示文档内容但禁止编辑
前置条件	用户通过有效的只读分享码（permission='view'）进入共享文档页面
基本事件流	                                               参与者动作：
1.1 进入 /share/:code 页面                                  1.2 系统请求 GET /api/share/:code，获取文档标题、内容及权限类型
2.1 —                                                       2.2 系统以只读模式渲染编辑器（editable=false），隐藏工具栏，页面顶部展示"只读分享"提示横幅
3.1 浏览文档内容                                             3.2 页面正常展示富文本内容（含代码块、超链接等格式）
4.1 点击"返回"按钮                                           4.2 系统根据来源页路径（location.state.from）返回上一页


其他事件流	无
异常事件流	1.2.1 分享码已失效或不存在：系统展示"该分享链接已撤销或不存在"提示及返回按钮
后置条件	用户完成文档浏览，未对文档内容产生任何修改
备注	前端 editable=false 禁用输入，后端 PUT /api/share/:code/content 亦对 view 权限返回 403，形成双重防护

## 通过分享链接编辑文档

用例名称	通过分享链接编辑文档
用例ID	UC13
角色	任意用户（含未登录游客，持有可编辑分享码）
用例说明	持有可编辑分享码的用户访问共享文档，可对文档内容进行修改并保存，修改归属于原文档所有者
前置条件	用户通过有效的可编辑分享码（permission='edit'）进入共享文档页面
基本事件流	                                               参与者动作：
1.1 进入 /share/:code 页面                                  1.2 系统请求 GET /api/share/:code，获取文档标题、内容及权限，以可编辑模式渲染编辑器
2.1 对文档内容进行修改（输入、删除、格式调整等）                  2.2 编辑器实时展示修改效果
3.1 点击"保存"按钮                                           3.3 系统向后端发送 PUT /api/share/:code/content，携带最新内容；后端验证分享码生效且权限为 edit 后，更新 documents 表对应记录的 content 与 updated_at
4.1 —                                                       4.4 系统提示"保存成功"


其他事件流	无
异常事件流	3.3.1 分享码已被撤销（保存时失效）：后端返回 404，前端提示"该分享链接已失效，内容无法保存"
3.3.2 网络异常：前端提示"保存失败，请重试"
后置条件	文档原内容已被更新，documents 表中 updated_at 刷新；文档作者归属不变
备注	匿名编辑通过 share_code 关联原文档，不修改文档 user_id；移动端使用 simple-editor-mobile 展示编辑器

## 撤销文档分享码

用例名称	撤销文档分享码
用例ID	UC14
角色	已登录用户（文档所有者）
用例说明	文档所有者在分享管理对话框中撤销某条分享链接，链接立即失效，持有该码的用户将无法继续访问
前置条件	用户已登录，打开了自己文档的 ShareDialog，且该文档存在至少一条生效的分享记录
基本事件流	                                               参与者动作：
1.1 在 ShareDialog 中找到目标分享码并点击"撤销"按钮             1.2 系统向后端发送 DELETE /api/doc/:id/share/:code
2.1 —                                                       2.2 后端联表校验 documents.user_id = 当前登录用户 ID，通过后将对应记录的 is_active 设为 false，记录 revoked_at 时间戳
3.1 —                                                       3.3 系统前端立即刷新 ShareDialog 本地状态，对应权限行切换为"生成"按钮


其他事件流	无
异常事件流	1.2.1 当前用户非该文档所有者：后端 WHERE 条件不满足，返回 404（不暴露记录存在性），前端提示"操作失败"
后置条件	对应分享码 is_active=false，历史记录保留用于审计；原分享链接持有者下次访问将收到"链接已失效"提示
备注	撤销采用软删除，不物理删除记录；部分唯一索引仅约束 is_active=true 的记录，撤销后可重新生成同权限分享码

1、ProseMirror 如何通过 Schema 机制定义文档模型（Document Model）？节点（Node）与标记（Mark）的结构与约束是如何描述的？

ProseMirror 通过 Schema 机制定义文档模型，具体包括：
- **节点类型定义**：在 Schema 中通过 `nodes` 属性列举可能出现的节点类型，每个节点类型通过 spec 对象描述，包括 `content` 字段定义允许的子节点序列。
- **内容表达式**：使用类似正则表达式的语法描述节点的内容约束，如 `paragraph+` 表示一个或多个段落。
- **标记类型管理**：通过 `marks` 属性定义允许的标记类型，如粗体、斜体等。
- **属性定义**：节点和标记可以通过 `attrs` 字段定义属性，如标题的级别、链接的 URL 等。
- **节点结构**：每个节点由 `type`（节点类型）、`content`（子节点片段）、`attrs`（属性）和 `marks`（标记数组）组成。
- **标记结构**：标记由 `type`（标记类型）和 `attrs`（属性）组成，存储在节点的 `marks` 数组中。

2、用户在编辑器中的操作（如插入、删除）是如何被抽象为 Transaction，并通过 Step 机制作用于文档状态（EditorState）的？

用户操作的处理流程：
- **事件捕获**：EditorView 捕获用户操作（如键盘输入、鼠标点击）。
- **事务创建**：将用户操作转换为 Transaction 对象，Transaction 是 Transform 的子类。
- **Step 生成**：Transaction 通过调用各种方法（如 `insertText`、`delete`）生成对应的 Step 对象，如 ReplaceStep、AddMarkStep 等。
- **状态更新**：调用 `state.apply(tr)` 将事务应用到当前状态，生成新的 EditorState。
- **视图更新**：EditorView 使用新状态更新 DOM 视图。

3、ProseMirror 如何将文档模型（Node Tree）映射为可编辑的 DOM 视图？其 View 层（EditorView）是如何实现最小化更新（incremental rendering）的？

文档模型到 DOM 视图的映射：
- **toDOM 方法**：Schema 中每个节点类型通过 `toDOM` 方法定义如何将节点转换为 DOM 结构。
- **DOM 生成**：EditorView 根据文档模型和 `toDOM` 方法生成可编辑的 DOM 元素。
- **最小化更新**：
  - 利用不可变数据结构的特性，比较新旧文档模型的差异。
  - 只更新文档中实际变化的部分，保留未变化节点的 DOM 结构。
  - 对于文本输入等操作，浏览器已经更新了 DOM，EditorView 会验证并确保 DOM 与状态一致。
  - 只在必要时更新 DOM 选择，避免干扰浏览器的选择状态。

4、文本样式（如加粗、斜体）在 ProseMirror 中是如何通过 Mark 表达的？Mark 的作用范围、存储方式以及与 Node 的关系是什么？

文本样式的表达：
- **Mark 定义**：在 Schema 的 `marks` 属性中定义标记类型，如 `strong`、`em` 等。
- **存储方式**：Mark 存储在节点的 `marks` 数组中，作为节点的元数据。
- **作用范围**：Mark 主要作用于内联内容，如文本节点。
- **与 Node 的关系**：
  - Mark 是节点的属性，附加到节点上。
  - 具有相同标记集的相邻文本节点会被合并。
  - 节点可以通过 `marks` 属性限制允许的标记类型。
- **DOM 映射**：Mark 通过 `toDOM` 方法映射为 DOM 元素，如 `<strong>`、`<em>` 标签。

5、Step 是如何描述文档变化的最小操作单元？Transform 又是如何组合多个 Step 实现复杂编辑操作的？

Step 和 Transform 的工作机制：
- **Step**：
  - 是文档变化的最小操作单元，如 ReplaceStep（替换文档部分）、AddMarkStep（添加标记）等。
  - 可以应用到文档上生成新文档。
  - 提供位置映射功能，用于更新文档变化后的位置。
- **Transform**：
  - 是 Step 的集合，用于组合多个 Step 实现复杂编辑操作。
  - 提供一系列方法（如 `delete`、`split`、`wrap` 等）来生成 Step。
  - 累积步骤映射，使用 Mapping 抽象来处理位置更新。
  - Transaction 是 Transform 的子类，增加了对选择和其他状态的管理。

6、ProseMirror 为什么采用不可变数据结构（immutable state）来表示文档？这种设计如何影响编辑器的更新机制？

采用不可变数据结构的原因：
- **状态一致性**：确保编辑器不会处于无效的中间状态，新状态可以瞬间替换旧状态。
- **代码清晰度**：不可变数据结构使代码更简单、更可预测。
- **历史跟踪**：支持撤销/重做功能，通过存储步骤的逆操作。
- **协作编辑**：便于实现多用户同时编辑。
- **高效更新**：通过共享未更改的子节点，减少内存使用和计算开销。

对更新机制的影响：
- **最小化更新**：比较新旧文档的差异，只更新变化的部分。
- **位置映射**：需要通过 Mapping 机制处理文档变化后的位置更新。
- **状态管理**：插件状态也必须是不可变的，通过 apply 方法在事务中更新。

7、ProseMirror 如何通过 Position（整数偏移）定位文档中的节点与文本？在文档变化后，位置是如何通过 Mapping 进行更新的？

位置定位与更新：
- **Position 定义**：使用整数偏移量表示文档中的位置，文档开始为 0。
- **位置计算**：
  - 进入或离开非叶节点算作一个标记。
  - 文本节点中的每个字符算作一个标记。
  - 叶节点（如图像）算作一个标记。
- **位置解析**：通过 `Node.resolve` 方法将位置解析为更具描述性的数据结构，包含父节点、偏移量等信息。
- **位置更新**：
  - Step 提供 `getMap` 方法生成位置映射。
  - Mapping 抽象收集一系列步骤映射，允许一次性映射多个步骤。
  - 通过 `map` 方法将旧位置映射到新位置，处理插入、删除等操作对位置的影响。

8、ProseMirror 的插件系统是如何扩展编辑器行为的？插件如何介入状态（state）、视图（view）以及事务（transaction）？

插件系统的扩展机制：
- **插件定义**：通过 `Plugin` 类创建插件，指定其行为。
- **介入状态**：
  - 通过 `state` 属性定义插件状态，包括 `init` 和 `apply` 方法。
  - 插件状态是不可变的，通过 `apply` 方法在事务中更新。
- **介入视图**：
  - 通过 `props` 属性定义视图属性，如事件处理、装饰、节点视图等。
  - 可以通过 `decorations` 属性添加装饰，影响文档的可视化呈现。
  - 可以通过 `nodeViews` 属性为特定节点类型定义自定义视图。
- **介入事务**：
  - 可以通过 `props` 中的事件处理函数捕获和处理事务。
  - 可以通过 `getMeta` 和 `setMeta` 方法在事务中附加和读取元数据。
  - 可以在 `apply` 方法中根据事务内容更新插件状态。

9、EditorState 内部包含哪些核心字段（doc、selection、storedMarks 等）？这些状态是如何在事务中演化的？

EditorState 的核心字段：
- **doc**：文档模型，是一个不可变的节点树。
- **selection**：当前选择，由 Selection 类的实例表示。
- **storedMarks**：当前存储的标记集，用于在输入时应用。
- **plugins**：插件集，存储插件及其状态。

状态演化：
- **doc**：通过事务中的 Step 应用更新，生成新的文档。
- **selection**：
  - 默认情况下，旧选择会通过每一步映射生成新选择。
  - 可以通过 `setSelection` 方法显式设置新选择。
- **storedMarks**：
  - 在文档或选择更改后自动清除。
  - 可以通过 `setStoredMarks` 或 `ensureMarks` 方法设置。
- **插件状态**：通过插件的 `apply` 方法在事务中更新。

10、ProseMirror 如何抽象光标与选区（Selection）？不同类型的 Selection（TextSelection、NodeSelection）如何影响编辑行为？

光标与选区的抽象：
- **Selection 类**：是选区的基类，定义了选区的基本属性和方法。
- **TextSelection**：最常见的选区类型，用于常规光标（锚点和头部相同）或选中文本。
- **NodeSelection**：用于选择单个文档节点，如按住 ctrl/cmd 键点击节点时。

不同类型的 Selection 对编辑行为的影响：
- **TextSelection**：
  - 两个端点都需要位于内联位置。
  - 用于常规文本编辑操作，如输入、删除、复制粘贴等。
- **NodeSelection**：
  - 选择范围从节点前的位置到节点后的位置。
  - 用于对整个节点进行操作，如删除、替换、移动等。

11、ProseMirror 如何实现文档模型（Node Tree）与 DOM 的解耦？为什么这种设计比直接操作 DOM 更可靠？

文档模型与 DOM 的解耦：
- **独立的数据结构**：文档模型是一个独立于 DOM 的数据结构，使用不可变设计。
- **toDOM 映射**：通过 Schema 中的 `toDOM` 方法将文档模型映射为 DOM 结构。
- **DOMParser 解析**：通过 `parseDOM` 属性从 DOM 解析文档模型，如处理粘贴操作。
- **状态驱动更新**：DOM 视图由文档模型驱动，而不是直接操作 DOM。

这种设计的优势：
- **状态一致性**：确保文档状态与 DOM 视图一致，避免 DOM 操作导致的状态不一致。
- **高效更新**：通过比较新旧文档模型的差异，实现最小化更新。
- **撤销/重做**：支持完整的撤销/重做功能，通过存储步骤的逆操作。
- **协作编辑**：便于实现多用户同时编辑，通过步骤的重排序和应用。
- **跨平台兼容性**：文档模型可以在不同平台上使用，不受 DOM 差异的影响。

13、以一段富文本为例详细讲讲从输入到最后完整可视化呈现的流程

以输入 "Hello <strong>world</strong>" 为例，完整流程如下：
1. **用户输入**：用户在编辑器中输入 "Hello "，然后按下粗体按钮，再输入 "world"。
2. **事件捕获**：EditorView 捕获键盘输入和按钮点击事件。
3. **事务创建**：
   - 输入 "Hello " 时，创建一个事务，调用 `insertText("Hello ")`。
   - 点击粗体按钮时，创建一个事务，调用 `setStoredMarks([schema.marks.strong.create()])`。
   - 输入 "world" 时，创建一个事务，调用 `insertText("world")`，此时会应用存储的粗体标记。
4. **Step 生成**：每个事务生成对应的 Step，如 ReplaceStep 用于插入文本。
5. **状态更新**：调用 `state.apply(tr)` 生成新的 EditorState，包含更新后的文档模型。
6. **DOM 映射**：EditorView 根据新的文档模型，通过 `toDOM` 方法生成对应的 DOM 结构。
7. **最小化更新**：比较新旧文档模型的差异，只更新变化的部分，如添加粗体标记的部分。
8. **可视化呈现**：浏览器显示最终的 DOM 结构，用户看到 "Hello <strong>world</strong>" 的效果。

通过以上流程，ProseMirror 确保了从用户输入到最终可视化呈现的整个过程都是可控、一致和高效的。
